# openshift-ai-bootstrap

Deploy Red Hat OpenShift AI (RHOAI) on OCP 4.22 with GPU support on AWS, GCP,
or Azure — using AgnosticD v2, Helm, and Argo CD GitOps. RHOAI serves as a
managed AI/ML platform for end users to run notebooks, pipelines, and model serving.

> **Status:** AWS ✅ verified (v0.1.0-aws) | GCP ✅ verified (v0.2.0-gcp) | Azure planned

---

## Prerequisites

You need accounts at three places before you can deploy:

| Account | What you get | URL |
|---|---|---|
| **demo.redhat.com** | AWS/GCP/Azure sandbox (Open Environment) with cloud credentials and a base domain like `sandbox1234.opentlc.com` | https://demo.redhat.com |
| **console.redhat.com** | OpenShift pull secret | https://console.redhat.com/openshift/install/pull-secret |
| **access.redhat.com** | Registry service account token to pull the RHOAI Helm chart from `registry.redhat.io` | https://access.redhat.com/terms-based-registry/ |

You also need a Linux or macOS machine with:
- `python3` ≥ 3.9
- `podman`
- `git`, `jq`, `aws-cli` (or `gcloud` / `az` for other clouds)
- `spec` v0.4.1 — [install](https://github.com/tosin2013/spec-status/releases/tag/v0.4.1)

## Quick Start

```bash
# 1. Clone this repo
git clone https://github.com/tosin2013/openshift-ai-bootstrap
cd openshift-ai-bootstrap

# 2. Run the bootstrap — installs prerequisites, sets up AgnosticD, validates readiness
./bootstrap.sh

# The bootstrap will prompt for:
#   - Cloud provider: aws / gcp / azure
#   - Account name: your sandbox ID (e.g. sandbox1234 from demo.redhat.com)
# Then it validates that secrets are filled. Run it again after filling secrets.
```

### Fill secrets (required before deployment)

The bootstrap creates the secrets directory and tells you what to fill in:

```bash
# 1. Main secrets file — pull secret + RHOAI registry credentials
vi ~/agnosticd-v2-secrets/secrets.yml
#   ocp4_pull_secret: '<paste from console.redhat.com>'
#   ocp4_workload_rhoai_registry_username: '<registry-service-account-name>'
#   ocp4_workload_rhoai_registry_password: '<registry-service-account-token>'

# 2. Per-account secrets — cloud credentials + base domain
cp ~/agnosticd-v2-secrets/secrets-sandboxXXX.yml \
   ~/agnosticd-v2-secrets/secrets-<your-sandbox-id>.yml
vi ~/agnosticd-v2-secrets/secrets-<your-sandbox-id>.yml
#   aws_access_key_id: '<from your Open Environment>'
#   aws_secret_access_key: '<from your Open Environment>'
#   base_domain: sandbox<NNN>.opentlc.com
```

### Validate readiness

```bash
# Run bootstrap again — must show 8/8 PASS before deploying
./bootstrap.sh --non-interactive
```

### Deploy

```bash
cd ~/agnosticd-v2

# AWS (primary)
./bin/agd provision \
  --guid rhoai01 \
  --config openshift-cluster \
  --account <your-sandbox-id>

# After ~60 minutes: check deployment_info.txt for login details
cat ~/openshift-ai-bootstrap/deployment_info.txt
```

## Post-Deploy

Set KUBECONFIG to access your cluster:

```bash
export KUBECONFIG=~/agnosticd-v2-output/rhoai01/openshift-cluster_rhoai01_kubeconfig
```

Verify RHOAI is fully operational:

```bash
# DataScienceCluster ready
oc get datasciencecluster -n redhat-ods-operator

# RHOAI dashboard URL
oc get route rhods-dashboard -n redhat-ods-applications -o jsonpath='{.spec.host}'

# GPU allocatable
oc get node -o jsonpath='{range .items[*]}{.metadata.name}: {.status.allocatable.nvidia\.com/gpu}{"\n"}{end}'
```

The `deployment_info.txt` file (auto-generated by the bootstrap after a successful
deploy) contains all login details: bastion SSH, OCP console URL, kubeadmin
password, and RHOAI dashboard URL.

## Architecture

```
openshift-ai-bootstrap/
  bootstrap.sh              ← onboarding script (runs onboard.yml)
  onboard.yml               ← manifest: prereqs, setup steps, validation
  vars/
    rhoai-aws.yml           ← AWS deployment config
    rhoai-gcp.yml           ← GCP deployment config
    rhoai-azure.yml         ← Azure deployment config
    secrets-template.yml    ← template for ~/agnosticd-v2-secrets/secrets.yml
  roles/
    ocp4_workload_rhoai/        ← installs RHOAI via Argo CD + rhai-on-openshift-chart
    ocp4_workload_validate_rhoai/ ← post-deploy validation (8 checks)
  docs/
    gpu-sizing.md           ← GPU instance sizing guide + model recommendations (AWS/GCP/Azure)
    dra-use-cases.md        ← Dynamic Resource Allocation use cases (MIG, time-slicing)
    gcp-service-account-troubleshooting.md  ← GCP SA key validation and RHPDS workaround
  specs/                    ← implementation specs tracked by spec-status
```

**Deployment flow:**

```
agd provision
  → openshift-cluster (OCP 4.22 IPI)
  → ocp4_workload_cert_manager
  → ocp4_workload_machinesets        (GPU node pool)
  → ocp4_workload_openshift_gitops   (Argo CD)
  → ocp4_workload_rhoai              (RHOAI via Helm + Argo CD)
  → ocp4_workload_validate_rhoai     (8 validation checks → PASS/FAIL)
```

---

## Validation Gate

Every deployment ends with `ocp4_workload_validate_rhoai` which checks:

1. DataScienceCluster `Ready`
2. RHOAI dashboard HTTP 200
3. NFD `NodeFeatureDiscovery` present
4. GPU node has NVIDIA CUDA driver label
5. GPU Operator `ClusterPolicy` ready
6. `nvidia.com/gpu` ≥ 1 allocatable
7. GPU Operator pods all Running
8. RHOAI application pods all Running

A deployment is only tagged as a release when all 8 checks emit `VALIDATION: PASS`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `./bootstrap.sh` fails validation | Check the fail message — most common: missing pull_secret or registry creds in `secrets.yml` |
| `agd provision` fails at bastion packages | Bastion uses RHEL 10 Hourly2 AMI (RHUI) — set in `agnosticd_images.bastion` in vars file |
| ArgoCD can't create DataScienceCluster | Run: `oc create clusterrolebinding openshift-gitops-rhoai-admin --clusterrole=cluster-admin --serviceaccount=openshift-gitops:openshift-gitops-argocd-application-controller` (automated in role for new deploys) |
| `nvidia.com/gpu` not allocatable | GPU Operator takes 5–10 min after ClusterPolicy is created — wait and re-check |
| Wrong cluster with `oc` commands | `export KUBECONFIG=~/agnosticd-v2-output/rhoai01/openshift-cluster_rhoai01_kubeconfig` |
| GCP `ASN.1 parsing error: short data` on provision | The RHPDS service account JSON has truncated PEM lines (a known RHPDS issue). Run `python3 scripts/validate-gcp-key.py ~/agnosticd-v2-secrets/gcp-service-account.json` — if it reports a line-length violation on lines 3 or 18, the key is corrupted. Download a fresh key from GCP Console → IAM → Service Accounts → Keys → Add Key → JSON |
| `agd destroy` fails — `HostedZoneNotEmptyException` | CloudFormation can't delete the Route53 zone because cluster DNS records remain. Clear them first: `aws route53 list-resource-record-sets --hosted-zone-id <ID>` then delete `api.*` and `*.apps.*` A records, then re-run `agd destroy` or `aws cloudformation delete-stack --stack-name openshift-cluster-<guid>` |
