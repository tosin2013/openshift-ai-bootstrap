## Summary

The ocp4_workload_rhoai role is structurally sound and follows the
`ocp4_workload_*` naming and variable-namespacing conventions. The provision
and destroy flows are well-formed. However, the `/agnosticd` skill review
identified two Must-Address gaps that mean the role will either fail during
provision or be rejected if submitted to the RHDP catalog: (1) the Argo CD
OCI registry credentials are conditionally created but always needed, and an
empty-credentials path will cause silent Argo CD sync failure; (2) the
stop/start/status lifecycle handlers are missing entirely. Additionally, the
single remaining unchecked task (ansible-lint) means the record is still ahead
of its evidence. The verdict is 🛑 RETHINK — the two Must-Address findings
must be fixed before the role can deliver its stated outcome.

## Findings

| ID | Severity | Category | Finding | Suggestion |
|----|----------|----------|---------|------------|
| F1 | 🎯 | outcome-miss | The Argo CD OCI registry secret (`rhoai-chart-registry`) is created unconditionally, but `username` and `password` fall back to empty strings when `registry_username`/`registry_password` are not defined. Argo CD will silently fail to pull `registry.redhat.io/rhai/rhai-on-openshift-chart`, meaning RHOAI is never installed. The outcome is not delivered. | Add `ocp4_workload_rhoai_registry_username` and `ocp4_workload_rhoai_registry_password` to `defaults/main.yml` (empty string defaults) and document that callers must supply these via secrets.yml. Add a pre-flight assert task that fails fast if both are empty: `ansible.builtin.assert: that: ocp4_workload_rhoai_registry_username != ''`. |
| F2 | 🎯 | outcome-miss | `tasks/main.yml` dispatches only `provision/create` and `destroy/remove`. There are no handlers for `stop`, `start`, or `status` ACTION values. Per the AgnosticD skill: *"Stop, start, and status operations are required for RHDP cost management — configs that do not implement them cannot be cost-controlled on the platform and will not be accepted for catalog submission."* An unknown ACTION silently does nothing, which masks the gap. | Add `stop.yml`, `start.yml`, and `status.yml` task files. For RHOAI as a workload (not infra), stop/start may be no-ops (RHOAI runs on the cluster; the cluster stop/start is handled at the config level), but each handler must exist and emit an informational message. Add the three dispatcher blocks to `tasks/main.yml`. |
| F3 | 💡 | roadmap-stale | `defaults/main.yml` defines `ocp4_workload_rhoai_chart_registry: "oci://registry.redhat.io/rhai/rhai-on-openshift-chart"` but this variable is never referenced in `workload.yml`. The Argo CD Application hardcodes `repoURL: "registry.redhat.io/rhai"` (Argo CD OCI repos omit the `oci://` prefix). The declared var and the actual value have different formats and the var is dead code. | Remove the unused var from `defaults/main.yml` or rename it to reflect the Argo CD repoURL format and reference it in the Application definition. |
| F4 | 💡 | outcome-miss (partial) | Helm install is not idempotent. Every provision run re-downloads and re-installs Helm v4 even if the correct version is already present on the bastion. This is unnecessary network I/O and makes re-runs slower. | Add a pre-check task: `ansible.builtin.command: helm version --short` with `register` and `failed_when: false`; skip the download/install block when the installed version matches `ocp4_workload_rhoai_helm_version`. |
| F5 | 💡 | roadmap-stale | `tasks/main.yml` unchecked (`specs/002-ocp4-workload-rhoai-role/tasks.md:10`): ansible-lint against the agnosticd EE image has not been run. After F1 and F2 are fixed, the role content will change, so lint must be re-run against the updated files. | Fix F1 and F2 first; then run `ansible-lint roles/ocp4_workload_rhoai/` inside the agnosticd EE image and tick the box once it passes. |
| F6 | 🤔 | roadmap-stale | `remove.yml` does not clean up the Helm binary installed to `/usr/local/bin/helm`. Depending on the bastion reuse policy, this may leave an unexpected binary behind after destroy. | Decide: if the bastion is ephemeral (destroyed with the cluster), no action needed. If the bastion is reused across deployments, add a cleanup task. Document the decision in the roadmap notes for 002 via `/speckit.roadmap.write`. |

## Recommended Actions *(proposed only — never auto-applied)*

**Must fix before proceeding:**

1. **F1 — Registry credentials preflight** (blocks Argo CD sync):
   - Add to `defaults/main.yml`:
     ```yaml
     ocp4_workload_rhoai_registry_username: ""
     ocp4_workload_rhoai_registry_password: ""
     ```
   - Add a preflight assert at the top of `tasks/workload.yml`:
     ```yaml
     - name: Assert registry credentials are set
       ansible.builtin.assert:
         that:
           - ocp4_workload_rhoai_registry_username | length > 0
           - ocp4_workload_rhoai_registry_password | length > 0
         fail_msg: >-
           ocp4_workload_rhoai_registry_username and
           ocp4_workload_rhoai_registry_password must be set
           (supply via secrets.yml).
     ```
   - Manual edit to `roles/ocp4_workload_rhoai/`, applied only after user approval.

2. **F2 — Add stop/start/status lifecycle handlers**:
   - Create `roles/ocp4_workload_rhoai/tasks/stop.yml`,
     `start.yml`, `status.yml` as informational no-ops (RHOAI lifecycle
     is managed at the cluster level, not the workload level).
   - Add dispatcher blocks to `tasks/main.yml` for `ACTION in ["stop"]`,
     `ACTION in ["start"]`, `ACTION in ["status"]`.
   - Manual edit, applied only after user approval.

**Recommended:**

3. **F3**: Remove the unused `ocp4_workload_rhoai_chart_registry` var from
   `defaults/main.yml`. Manual edit after approval.
4. **F4**: Add a Helm version pre-check to make provision idempotent.
   Manual edit after approval.
5. **F5**: Re-run ansible-lint after F1 and F2 are applied; tick
   `tasks.md:10` once it passes.

findings (F1, F2) mean the role will not deliver its stated outcome as written.
Recommended path: fix F1 and F2 → re-run ansible-lint → re-run this debrief →
